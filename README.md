
# My week 2 experience at Luxdev HQ as a Data Science Student


# Weekly Learning Reflection: Git, GitHub and Emerging Technical Skills

This week, I made significant progress in building my first GitHub project and developing a more practical understanding of Git, version control and command-line workflows. I learned several new processes, including creating and organising directories and folders, navigating project structures through Git Bash and using `nano` to create and edit files directly from the command line instead of relying on `echo`. I also practised staging changes, committing updates and pushing my project from Git Bash to GitHub.

The tutor, Bridget, has been firm in maintaining the pace and expectations of the course, while remaining professional and supportive. This approach has encouraged me to take greater responsibility for practising independently and understanding the processes rather than simply following commands during the sessions.

One of the main challenges has been becoming comfortable with the command-line workflow and remembering the correct sequence of commands. Moving between creating directories, navigating folders, editing files with `nano`, staging changes and pushing updates can sometimes be confusing, particularly when a small error affects the next step. I am addressing this through repeated practice, documenting commonly used commands and recreating the processes independently.

Over the weekend, I also joined a class on **Deploying Machine Learning Models with FastAPI**, hosted by Harun. I left after approximately 30 minutes because the concepts were beyond my current level of understanding. However, the session gave me an appreciation of the technical skills involved in moving a machine learning model from development into a usable application. Although I was unable to follow the class at this stage, I look forward to revisiting the topic as my understanding of Python, machine learning and software development improves.

The availability of class recordings has also been particularly helpful. They provide an opportunity to revisit concepts and repeat processes at an individual pace. At times, however, the recordings can feel repetitive or become confusing when several processes are demonstrated in succession. This makes it difficult to quickly identify the exact steps required when revising a specific task.

# Recommendations

One recommendation would be to create short, structured tutorial recordings for key technical processes. These could be prepared by a tutor and organised around specific tasks, such as setting up Git, creating a repository, configuring GitHub, using `nano`, committing changes and pushing projects. Where processes differ between operating systems, the tutorials could include clear recommendations or separate instructions for Windows, macOS and Linux users. These recordings could then be uploaded online or shared alongside the main class recordings as a reliable reference and revision resource.

Another recommendation would be to develop a concise step-by-step reference guide or command cheat sheet for each module. This could summarise the correct workflow, common commands, expected outputs and common errors. Such a resource would reduce the need to repeatedly search through long class recordings and would help learners practise independently between sessions.

Overall, the experience has been challenging but valuable. I am increasingly comfortable with Git and GitHub, and I am looking forward to strengthening my understanding of branches, merge conflicts, collaborative workflows and, eventually, more advanced topics such as deploying machine learning models and applications.
